Context the next session needs (it will not see this audit unless quoted here): FinSight mobile is an Expo/React Native app for a small-business owner (likely Philippines-based, per Filipino-language synonyms found elsewhere in the codebase) tracking expenses/sales and reading a "Recovery Meter" financial-health signal, often from receipt photos. This is a REFINE pass on an app with no running simulator available in this environment — verify changes by reading rendered output/tests, not by assuming a live device screenshot.

Fix in priority order (top 5 moves from the audit, verbatim):
1. #10/#4 — Consolidate segmented-control/pill sprawl: seven independent re-implementations of "select one of N options" exist with no shared component — `InsightsScreens.tsx:14-44` (InsightTabs), `:89-107` (period toggle), `DashboardScreen.tsx:88-109` (PERIODS), `RecordsScreens.tsx:168-195` (FilterChip), `:537-572` (CategoryChips), `:614-699` (CategoryPicker inline chips), `:1740-1763` (CSV header chips), `DateField.tsx:165-217` (DateRangeChips). Build one shared primitive in `ui.tsx` and migrate all seven call-sites to it.
2. #8 — Add focus and success states app-wide: zero `onFocus` handling exists anywhere (grep confirmed empty) — every TextInput/Field keeps a static border regardless of keyboard focus. Success feedback is missing on Dashboard, the Records list, all three Insights tabs, and Notifications (it already exists correctly in Auth, Scan Receipt, and CSV Import — use those as the reference pattern).
3. #4 — Plain-language the flagship value-prop terms: "Recovery target," "Adjusted daily target" (`RecoveryMeter.tsx:69`), "Sales reference" (`DashboardScreen.tsx:149`), "Large-expense threshold (%)" (`BusinessScreens.tsx:274`) need either a rename or inline plain-language subtext for a first-time small-business-owner user.
4. #10 — Delete or wire up 5 confirmed-dead components and 3 unused props: `ExecutiveSummaryCard`, `Pill`, `Divider` (`ui.tsx:307-344,255-303,531-533`), `SeriesDot`, `HeroFigure` (`charts.tsx:421-432,389-418`) have zero call-sites; `Alert.action` (`ui.tsx:211,235`), `Money.bare`/`Money.decimals` (`ui.tsx:59-60`), `RecoveryMeter.compact` (`RecoveryMeter.tsx:18`) are defined/rendered but never passed by any caller. For each, decide: ship it (wire up a real caller) or delete it — no third option.
5. #9 — Parallelize the bootstrap chain and respect reduced-motion: `auth/me` → `/business-profiles` → `/records/categories` run sequentially via effect-chaining (`AuthContext.tsx:51-58`, `BusinessProfileContext.tsx:37-46,64,67-69`) rather than `Promise.all`'d where their dependencies allow; separately, `AccessibilityInfo.isReduceMotionEnabled` has zero matches repo-wide — gate the loading shimmer (`Skeleton.tsx:16-35`) and the AskFinSight sheet animation (`AskFinSight.tsx:98-113,153`) on it.

Bundle-in quick win: `RecoveryMeter.tsx:81` hardcodes `#e8efed`, an exact duplicate of the `paper[200]` token (`tokens.ts:77`) — swap to the token import while touching that file for move #2.

Also worth folding into this plan (raised directly by the requester, not separately scored by the Rams audit but relevant to the same files):
- Accessibility gaps found alongside the above: no `returnKeyType`/`onSubmitEditing` chaining in any multi-field form (Auth, BusinessProfile, Add/Edit Expense/Sales, Scan Receipt) — add logical keyboard "next" order. `accessibilityRole="button"` is missing at `DashboardScreen.tsx:155-166`, `InsightsScreens.tsx:90-107,288-300`, `RecordsScreens.tsx:1745-1759` — add it. Swipe-to-delete/resolve (`RecordsScreens.tsx:140-164`) has no non-gesture fallback for assistive-tech users — consider a visible action button as an alternative to the swipe gesture. The one `<Image>` in the app (`PhotoUpload.tsx:87`) has no `accessibilityLabel`.
- `ink[400]` (3.36:1 contrast, documented in `tokens.ts:65` as "decorative/placeholder only") is the default color of the `caption` variant (`ui.tsx:34`), used 95 times for functional text (dates, hints, chart axis labels) — this is a live AA-body-text contrast failure, not just a documented carve-out. Either bump the `caption` variant's default to `ink[500]`+ or introduce a genuinely-decorative-only token distinct from `caption`.

Out of scope for this refine pass: information architecture, navigation structure (bottom tabs / stack layout), the token system's color/type/spacing *values* themselves (only usage discipline is in scope, not the palette or scale definitions), and any new screens or features.

Anti-patterns to guard against (specific to REFINE):

- Restyling areas that already scored 3 (Dashboard's single-call data flow, the disclaiming AI copy, the flat/durable visual language) — touch them only where a listed fix requires it

- Letting fixes mutate principles outside the priority list — e.g. don't "improve" copy tone beyond the 4 flagged jargon terms, don't touch the color palette while fixing the one contrast issue
