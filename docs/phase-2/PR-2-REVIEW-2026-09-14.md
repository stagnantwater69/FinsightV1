## Open P2 items and the owner's dispositions (14 September 2026)

The owner accepted the recommended defaults: item 1 accepted for the development project with a runbook requirement before any real-owner deployment; items 2 and 3 fixed in a mobile lane the same day; item 4 deferred to after merge.

1. **Backfill of `lastActivityAt` and the first sweep after a deploy.** The migration backfills the clock from timestamps that never recorded owner views, so a pending scan the owner merely opened last week is treated as inactive since its last recorded event. On the hosted development project this has already happened: the owner deployed `20260914010610` at about 02:07 PHT on 14 September and started the worker with the sweep code before the boot-time sweep was removed. **Disposition: accepted for the development project (synthetic data).** A forward-only grace migration (floor `lastActivityAt` at deploy time minus six days for unconfirmed scans) is now a documented requirement in the deployment runbook, §5, before any real-owner deployment. Owner: database, at that time.
2. **Mobile Receipts to finish is stale after Retake photo, Choose another image, or Choose another receipt** ([`ScanReceiptScreen.tsx:491`](../../mobile/src/screens/records/ScanReceiptScreen.tsx#L491)). The mobile twin of web P2-11: the abandoned server-side scan is invisible on this screen until it is blurred and refocused. **Disposition: fix now. Fixed** the same day: `resetForAnotherReceipt` seeds the abandoned pending scan (and accepted pending batch children) into the list via the new [`activeReceipts.ts`](../../mobile/src/screens/records/scanReceipt/activeReceipts.ts) helpers and refreshes; a failed refresh keeps the rows and the existing Check again path. Three render tests in `receiptImportFlow.test.tsx` failed before the change and pass after.
3. **Delete stored scan during a partially accepted batch discards never-uploaded receipts** ([`ScanReceiptScreen.tsx:1083`](../../mobile/src/screens/records/ScanReceiptScreen.tsx#L1083)) and tells the owner they remain available. **Disposition: fix now. Fixed** the same day: `deleteStoredScan` keeps never-uploaded groups (and their files) as a fresh capture session and the flash names exactly what remains. One new test and one extended test failed before the change and pass after. Physical-device verification of the promoted-pages camera path is still required.
4. **Web pre-fetched duplicate acknowledgement is keyed to the worker's fingerprint** ([`ScanReceipt.tsx:383`](../../web/src/pages/ScanReceipt.tsx#L383)), so any field edit before Save forces a second "matches changed" acknowledgement even when the candidate list is identical. The fix touches how the client computes the acknowledged set; the server contract is unchanged. **Disposition: after merge.** Owner: web-frontend, with backend-api consulted on the hash inputs.
