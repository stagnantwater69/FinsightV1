## Open P2 items and the owner's dispositions (14 September 2026)

The owner accepted the recommended defaults: item 1 accepted for the development project with a runbook requirement before any real-owner deployment; items 2 and 3 fixed in a mobile lane the same day; item 4 deferred to after merge.

## Physical-device findings (owner-reported, 14 September 2026)

Poco X6 5G, Android version not yet recorded, APK built before the P2 changes:

1. **P1, mobile: native Standard capture never accepts a frame on a real paper receipt.** `Capture now` switches the guidance to "Checking receipt edges…" and stays there indefinitely; no capture and no missing-edge or poor-quality message. First observed on a receipt image shown on a screen (not a valid scene), then reproduced by the owner on a real paper receipt. Scene, from the owner's later screenshot: a wrinkled thermal receipt lying on patterned pink fabric under room light. That is the busy, low-contrast background the on-screen guidance tells the owner to avoid, so the detector's refusal is consistent with its design; the P1 stands only if a flat receipt on a plain contrasting surface also fails, which is the pending retest. Two defects were implied before the scene was known: the detector does not accept a real handheld scene that a person can see is a receipt (the 7 September capture fix was verified only on synthetic scenes), and the arm-and-report path is not surfacing its failure reason, which that fix said it would. Next: capture `adb logcat` from the device during an attempt, or a plain photo of the scene, then reproduce with the instrumented build.
2. In Expo Go the same screen works because the native module is absent there and the plain shutter is used; that is not evidence for the native path. Manual sections and Gallery remain the working capture paths on the device.

On a wrinkled receipt over patterned fabric this is within local Tesseract's documented limits and is not a regression. **P3, ai-ocr-analytics:** the vendor heuristic should not prefer a footer line containing a person's name over a header line; add this receipt's layout to the corpus when a consented copy is available.
